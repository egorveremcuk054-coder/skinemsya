# Скинемся 💸

REST API для дележа общих расходов: поездки, съёмная квартира, общие покупки.
Участники записывают, кто за что платил, а сервис считает, кто кому должен,
и предлагает **минимальное число переводов**, чтобы рассчитаться.

## Возможности

- Регистрация и вход по JWT
- Группы с участниками: зарегистрированными пользователями и «гостями» (только имя)
- Траты с тремя способами деления: **поровну**, **точными суммами**, **по долям** (2:1:1)
- Балансы участников и список переводов «кто кому сколько»
- Учёт уже сделанных переводов
- Доступ к группе только у её участников; чужая группа для API не существует (404)
- Документация в Swagger UI

## Как это работает

Поездка в Питер, трое участников:

- Аня оплатила жильё — 6000 ₽ на всех;
- Борис оплатил бензин — 3000 ₽ на всех.

Если каждый вернёт долю каждому, кто платил, получится 4 перевода. Сервис считает балансы:

| Участник | Заплатил | Доля | Баланс |
|----------|---------:|-----:|-------:|
| Аня      | 6000     | 3000 | +3000  |
| Борис    | 3000     | 3000 | 0      |
| Вика     | 0        | 3000 | −3000  |

И предлагает **один** перевод: Вика → Аня, 3000 ₽.

## Алгоритмы

Баланс участника — сколько он заплатил минус его доля во всех тратах.
Сумма балансов всегда равна нулю. Задача — превратить балансы в переводы.

**Жадный алгоритм** — [`GreedyDebtSimplifier`](src/main/java/ru/skinemsya/core/GreedyDebtSimplifier.java).
Самый большой должник переводит самому большому кредитору меньшую из двух сумм, и так до нуля.
Каждый перевод обнуляет хотя бы одного участника, поэтому переводов не больше `n − 1`.
Работает за `O(n log n)` на двух очередях с приоритетом.

**Точный алгоритм** — [`OptimalDebtSimplifier`](src/main/java/ru/skinemsya/core/OptimalDebtSimplifier.java).
Жадный подход не всегда оптимален. Пример: балансы `A +5, B +4, C −2, D −3, E −4`.
Жадный алгоритм сделает 4 перевода, а можно обойтись тремя: группа `{A, C, D}` закрывается
двумя переводами, а `{B, E}` — одним.

В общем виде: если участников можно разбить на `k` групп с нулевой суммой балансов,
понадобится `n − k` переводов. Поиск максимального `k` — NP-трудная задача, поэтому она решается
динамикой по подмножествам за `O(2ⁿ · n)`. Это быстро до ~20 участников с ненулевым балансом.

**В API** используется [`AdaptiveDebtSimplifier`](src/main/java/ru/skinemsya/core/AdaptiveDebtSimplifier.java):
точный алгоритм для групп до 16 должников и кредиторов, жадный — для больших.

### Деньги

- Суммы хранятся в копейках в `long`, а не в `double`: `0.1 + 0.2` в `double` даёт `0.30000000000000004`.
- Все операции проверяют переполнение (`Math.addExact` и т.п.).
- При делении копейки не теряются: 100 ₽ на троих — это `33,34 + 33,33 + 33,33`.
  Деление по долям использует метод наибольших остатков.

Ядро с алгоритмами (`ru.skinemsya.core`) написано на чистой Java без Spring и покрыто
юнит-тестами, включая проверку на случайных данных: точный алгоритм никогда не хуже жадного,
а после переводов все балансы нулевые.

## Стек

- **Java 21**: records, sealed-интерфейсы, `switch` по enum
- **Spring Boot 4**: Web MVC, Data JPA, Validation, Security (OAuth2 Resource Server + JWT), Actuator
- **PostgreSQL 17** + **Flyway**
- **springdoc-openapi**: Swagger UI
- **JUnit 5**, **AssertJ**, **MockMvc**, **Testcontainers**
- **Docker**, **Docker Compose**, **GitHub Actions**

## Архитектура

Пакеты разделены по фичам. Ядро не зависит от Spring и базы данных.

```
ru.skinemsya
├── core         алгоритмы на чистой Java: Money, Split, BalanceCalculator, *DebtSimplifier
├── user         регистрация, вход, текущий пользователь
├── security     настройки Spring Security, выпуск JWT
├── group        группы и участники, проверка доступа
├── expense      траты и способы деления
├── settlement   сделанные переводы
├── balance      балансы и рекомендуемые переводы (связывает БД и ядро)
└── common       обработка ошибок (RFC 9457 Problem Details), OpenAPI
```

Схема БД — в [миграции Flyway](src/main/resources/db/migration/V1__init.sql).

## API

Все запросы, кроме `/api/auth/**`, требуют заголовок `Authorization: Bearer <token>`.

| Метод    | Путь                                         | Что делает                          |
|----------|----------------------------------------------|-------------------------------------|
| `POST`   | `/api/auth/register`                         | Регистрация                         |
| `POST`   | `/api/auth/login`                            | Вход, возвращает JWT                |
| `GET`    | `/api/users/me`                              | Текущий пользователь                |
| `POST`   | `/api/groups`                                | Создать группу                      |
| `GET`    | `/api/groups`                                | Мои группы                          |
| `GET`    | `/api/groups/{id}`                           | Группа с участниками                |
| `DELETE` | `/api/groups/{id}`                           | Удалить группу (только создатель)   |
| `POST`   | `/api/groups/{id}/members`                   | Добавить участника по имени или email |
| `POST`   | `/api/groups/{id}/expenses`                  | Добавить трату                      |
| `GET`    | `/api/groups/{id}/expenses`                  | Траты группы                        |
| `DELETE` | `/api/groups/{id}/expenses/{expenseId}`      | Удалить трату                       |
| `GET`    | `/api/groups/{id}/balances`                  | Балансы участников                  |
| `GET`    | `/api/groups/{id}/settle-up`                 | Как рассчитаться: минимум переводов |
| `POST`   | `/api/groups/{id}/settlements`               | Отметить сделанный перевод          |
| `GET`    | `/api/groups/{id}/settlements`               | История переводов                   |
| `DELETE` | `/api/groups/{id}/settlements/{settlementId}` | Удалить перевод                    |

Полная документация с примерами: **http://localhost:8080/swagger-ui.html**

### Примеры трат

```jsonc
// Поровну между всеми участниками группы
{ "description": "Жильё", "amount": 6000, "payerId": 1, "split": { "type": "EQUAL" } }

// Поровну между некоторыми
{ "description": "Бензин", "amount": 3000, "payerId": 2,
  "split": { "type": "EQUAL", "memberIds": [1, 2] } }

// Точными суммами
{ "description": "Ужин", "amount": 2500, "payerId": 1,
  "split": { "type": "EXACT", "parts": [ { "memberId": 1, "amount": 1500 }, { "memberId": 3, "amount": 1000 } ] } }

// По долям 2:1:1
{ "description": "Продукты", "amount": 1000, "payerId": 3,
  "split": { "type": "SHARES", "parts": [ { "memberId": 1, "share": 2 }, { "memberId": 2, "share": 1 }, { "memberId": 3, "share": 1 } ] } }
```

Ошибки возвращаются в формате Problem Details:

```json
{
  "status": 400,
  "detail": "Сумма долей (900,00 ₽) не совпадает с суммой траты (1000,00 ₽)"
}
```

## Запуск

Нужны **JDK 21** и **Docker**.

### Из IntelliJ IDEA

1. Запустите Docker Desktop.
2. Запустите `SkinemsyaApplication`. Spring Boot сам поднимет PostgreSQL из `compose.yaml`.
3. Откройте http://localhost:8080/swagger-ui.html, зарегистрируйтесь через `/api/auth/register`,
   получите токен в `/api/auth/login` и вставьте его в «Authorize».

### Всё в Docker

```bash
docker compose --profile app up --build
```

Приложение будет доступно на http://localhost:8080.

### Тесты

```bash
./mvnw verify
```

Интеграционные тесты поднимают настоящий PostgreSQL в контейнере через Testcontainers,
поэтому Docker должен быть запущен. На Windows вместо `./mvnw` используйте `mvnw.cmd`.

### Настройки

| Переменная                   | Назначение                                              |
|------------------------------|---------------------------------------------------------|
| `JWT_SECRET`                 | Секрет для подписи токенов, Base64, минимум 32 байта    |
| `SPRING_DATASOURCE_URL`      | Адрес PostgreSQL, если запускаете без Docker Compose    |
| `SPRING_DATASOURCE_USERNAME` | Пользователь БД                                         |
| `SPRING_DATASOURCE_PASSWORD` | Пароль БД                                               |

Значение `JWT_SECRET` по умолчанию подходит только для локальной разработки.
